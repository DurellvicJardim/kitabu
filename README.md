# Kitabu

Kitabu is an Android app for booking books out of a library, written in Kotlin with Jetpack Compose and Room.

The first screen is the catalog. Every book shows its cover, author, category and whether it is on the shelf, and you can search by title or author or narrow the list to what is available. Tapping an available book opens a sheet where you give your name and pick the date you will bring it back. A book that is already out shows the date it comes back instead, so you know when to check again. The second screen is your bookings, sorted by whatever is due first. Each one says when it was reserved, when it is due and how many days are left, with overdue items and anything due today in red. A reservation can be marked as collected or cancelled. Once it has been collected you can return the book or renew it to a later date. A reservation is refused if the name is blank, if no return date was chosen, or if that date is today or earlier. A renewal has to be later than both the current due date and today. The first two complain under the field in the sheet, the rest come back as a snackbar. The library starts with thirteen textbooks and four bookings already on the go. Those dates are worked out from the day the app first runs, so one booking is always overdue, one is due today, one still has days left and one is waiting to be collected.

## How it is put together

The code sits in four packages under `com.durelljardim.kitabu`. `data` holds the tables, the queries that read and write them, the database itself and the starting data, `domain` holds the joined booking model and the date helpers, `ui` holds the screens, the shared ViewModel and the theme, and `di` holds the small container that wires everything together. Room stays inside `data` and Compose stays inside `ui`. The screens read state from a ViewModel, the ViewModel goes through a repository, and the repository is the only class that talks to the database. Nothing is injected by a library. `KitabuApplication` builds an `AppContainer`, which creates the database and the repository, and `AppViewModelProvider` passes that repository to the ViewModel.

There are two tables. Books have a title, author, category and an availability flag. Bookings record who has the book, when it was booked, when it is due and its status, with a foreign key onto the book that cascades on delete and an index on that column. Reserving, cancelling and returning a book each write to both tables, so those writes run as transactions and a booking can never be saved against a book that is still marked available. Reads come back as flows, so a write shows up on screen without anything asking for a refresh. Both screens share one `LibraryViewModel`. The search text and the availability filter are state flows, and when either changes `flatMapLatest` swaps in the query that matches, so the filtering happens in SQL rather than over the loaded list. That is combined with the bookings and the pending snackbar message into one state object, held with `stateIn` and `WhileSubscribed`, so turning the phone does not restart the queries. The screens take their state and their callbacks as parameters and only remember small things of their own, like which book the reserve sheet is open for.

SQLite has no date type, so dates are stored as epoch milliseconds and converted in one place. Days are counted with `LocalDate` and `ChronoUnit.DAYS.between` rather than by dividing milliseconds, which keeps "Due today" and "Overdue by 4 days" right whatever the time is. The Material date picker works in UTC, so it converts with UTC both ways, and past days are greyed out in the picker instead of being rejected after the fact. The look is ink blue on warm off-white, serif for book titles, and a single column of cards. Dark mode follows the phone. The available and borrowed badges keep their own green and orange in both themes so they stay easy to tell apart. It is built for one person, so there are no accounts and the name is typed in each time. A schema change drops the database rather than migrating it. There are no automated tests. Cover images come from Open Library and the icons are Material Symbols. The container and ViewModel factory follow the pattern taught in Google's Android Basics with Compose inventory app.
